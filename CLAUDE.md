# Tempelhofer Feld Activity Forecast

Weather-based activity scoring app for Tempelhofer Feld in Berlin. Provides hourly forecasts optimized for cycling, jogging, kiting, and picnics with activity-specific scoring algorithms.

## Architecture

### Scoring System (Penalty-Only)
All activities start at 100 points. Only penalties reduce score (no bonuses).

One engine, `scoreHour(activity, hour)`, scores every activity from `SCORING_CONFIG` and returns a
`ScoreBreakdown` (`score`, `status: open|closed|thunderstorm`, sorted `penalties[]`, `crowd`). The UI
shows the breakdown in the detail modal ("What's holding it back"). `calculateCyclingScore()` etc. are
thin wrappers kept for compatibility. The explainer text is generated by `explainActivity()` from the
same config, so documented numbers can't drift from applied ones.

- Cycling - Wind -40, Rain -55 (continuous by probability + intensity), Cold -40 (12°C), Crowds -25
- Jogging - Heat -35 (22°C), Rain -32 (continuous), Cold -20 (10°C), UV -25
- Kiting - Wind critical (5-11 m/s workable, continuous ramps outside), Gustiness -40, Cold -40 (10°C), Rain -40
- Socializing (picnic) - Rain -70 (continuous), Wind -40, Cold -35 (15°C), UV -30, No sun -20 (cloud cover, daylight only)

Air quality uses the real European AQI (CAMS) mapped onto the 1-5 config scale (`aqiLevel`: ≤20 → 1,
40 → 2, 60 → 3, 80 → 4). No AQI data → no AQI penalty (never a made-up value).

### Crowd Model (`src/utils/crowd.ts`)
`index = 100 × dayLevel × diurnalProfile(hour, sunset) × weatherAttraction` (multiplicative, 0-100,
100 = peak hour of a sunny ~25°C Sunday).
- Day levels (Sunday/holiday 1.0, Saturday 0.755, weekday 0.343) are *solved* so integrated daily
  profiles reproduce Besuchermonitoring 2014 counts (weekday 12,598 / Sat 25,614 / Sun 31,040 visits,
  × mean visit duration from the 2023 survey). `crowd.test.ts` enforces this within 3%.
- Peaks are anchored to sunset (autumn 2012 monitoring: weekday 16:30, Sat 14:30, Sun 14:00), so they
  move later in summer. Continuous twilight ramp before sunrise / after sunset.
- Berlin public holidays (incl. Women's Day, Easter-based) behave like Sundays; Friday from 15:00 ×1.15 (assumption).
- Weather: warmth (smoothstep 2→24°C, decline above 28°C, no shade), rain (probability + intensity),
  sunshine, wind. These response curves are informed assumptions, not fitted.
- Levels: quiet <15, moderate <35, busy <60, very busy ≥60.

### Data Flow
1. Frontend requests weather data from Netlify Function (`/.netlify/functions/weather`)
2. Function checks cache (Netlify Blobs via `connectLambda(event)`, falls back to in-memory; key `weather-data-v2`)
3. If cached and fresh (<1 hour old): Return cached data immediately
4. If stale or missing: Fetch fresh data from Open-Meteo in parallel
   - Forecast: one request with `past_days=1&forecast_days=7&timeformat=unixtime` (today's earlier hours included)
   - Air quality (`european_aqi`, 5 days): non-fatal, scoring skips AQI without it
   - `netlify/lib/openMeteo.ts` converts to hour slots: drops hours before Berlin midnight, shifts
     "preceding hour" aggregates (precipitation, its probability, gusts) onto the slot they describe
5. Cache the fresh data (Blobs if available, otherwise in-memory). If Open-Meteo fails, serve the last
   good data up to 12 h old (`stale: true`); otherwise 502. Production never shows mock data.
6. Frontend scores client-side (`scoreHour`) in Berlin time regardless of the viewer's timezone

### Layout
- 2-row grid per day (2x12 on desktop, 2x6 on mobile); 4 days shown, "Show 3 more days" toggle (7-day data)
- Best Times to Go: top 3 non-overlapping 2-hour windows (avg visit ≈ 2 h) from now to the end of day 4,
  each with its main drawback; each day header shows that day's best window
- Activity selector: 2x2 grid on mobile, 1x4 on desktop (choice remembered in localStorage)
- Compact cards: time ("Now" + ring for the current hour), score, temp, wind, rain %, crowd dots
- Detail modal: score breakdown, weather, crowds, AQI, UV, clouds, visibility (Esc/backdrop closes)
- Header: today's opening hours, sunset, last update time

## Design Decisions

**Temperature sensitivity:**
- Picnic most sensitive to cold (15°C threshold, sitting still)
- Cycling moderately sensitive (12°C threshold)
- Jogging less sensitive (10°C threshold, you warm up)
- Heat worse for jogging than cycling (overheating risk)

**Wind requirements:**
- Kiting requires wind: 5-11 m/s workable (no penalty); continuous ramps outside:
  4 m/s = -22, 3 m/s = -51, ≤1.5 m/s = -100; 12 m/s = -12, 13 m/s = -30, 14 m/s = -51, ≥16 m/s = -100
- Kiting gustiness: gusts more than 5 m/s above the mean wind cost up to -40
- Cycling/Picnic: wind is penalty (affects comfort, stability)
- Jogging: minimal wind penalty (lower profile)

**Rain sensitivity (fully continuous, no binary switch):**
- Socializing: worst (maxPenalty -70, steepest curve, ruins food/blankets)
- Cycling: severe (maxPenalty -55, wet roads, poor visibility)
- Kiting: moderate (maxPenalty -40, wet equipment)
- Jogging: lightest (maxPenalty -32, runners tolerate rain)

**Crowd estimation:**
- Multiplicative model calibrated to real visitor counts (see Architecture → Crowd Model)
- Kiting: highest penalty multiplier (0.35, safety/space)
- Cycling: moderate multiplier (0.25, navigation)
- Socializing: moderate multiplier (0.25, less of an issue)
- Jogging: minimal multiplier (0.10, easy to navigate)

## Data Source: Open-Meteo API

**Why Open-Meteo:**
- 100% free, no API key, unlimited requests
- Hourly forecasts up to 16 days
- Uses DWD (ICON model) + European weather models
- Historical data API for proper past hours
- Clean JSON API, easy to parse

**API Endpoints:**
```
https://api.open-meteo.com/v1/forecast
  ?latitude=52.4732&longitude=13.4053
  &hourly=temperature_2m,apparent_temperature,precipitation_probability,precipitation,weather_code,cloud_cover,visibility,wind_speed_10m,wind_direction_10m,wind_gusts_10m,uv_index,is_day
  &timezone=Europe/Berlin&timeformat=unixtime&past_days=1&forecast_days=7&wind_speed_unit=ms

https://air-quality-api.open-meteo.com/v1/air-quality
  ?latitude=52.4732&longitude=13.4053&hourly=european_aqi
  &timezone=Europe/Berlin&timeformat=unixtime&past_days=1&forecast_days=5
```

**Hour semantics:** temperature, wind, clouds, UV are instantaneous; precipitation, precipitation
probability and gusts cover the *preceding* hour. Slot `[t, t+1h)` takes those from the `t+1h` record.
